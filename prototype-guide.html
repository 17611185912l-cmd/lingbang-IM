领榜家教消息与聊天原型说明

版本：2026-11-16｜本次范围：教师详情的聊天入口、消息页私信、用户与顾问聊天。

本文以当前本地原型代码为依据，逐项描述范围内的交互、字段、点击去向和判断。姓名、头像、编号、日期等均为演示数据，不作为真实业务记录。

1. 本次范围与共用规则

1.1 范围边界

范围本文描述内容
教师详情的聊天入口仅描述“联系芦顾问”如何进入会话、携带哪位老师以及双方自动开场
消息页面仅描述私信行的字段、摘要更新、空态及点击进入聊天
用户与顾问聊天双视角、资料条、文本输入发送、常用语、加号、图片、老师/需求单/订单卡片、老师筛选、添加微信
聊天附件的外部目标仅说明点击去向及返回会话时的数据保留，不展开目标业务详情

首页、通知归类与通知详情、教师详情其余功能不属于本次说明。现有页面和功能继续保留，本次仅维护文档与右侧规则面板。

1.2 当前状态与刷新口径

字段/状态初始值本轮保留及刷新规则
chatMessages空数组，0条本次运行共用；刷新清空
nextMessageId从1开始每新增一条加1；刷新重置
chatRoleuser，用户视角普通往返保留；详情聊天入口强制user
drafts用户/顾问各为空字符串两份独立保留；刷新清空
私信摘要/时间暂无消息/空随最后一条聊天记录更新；无伪造“刚刚”
chatPanelnull常用语/加号面板互斥；关闭与切换规则见第6章
图片、卡片选择、微信名片关闭临时状态；离开聊天或切视角按下文清理

聊天记录、草稿和附件只在当前运行内存中，不写localStorage、数据库或真实接口。重新打开原型标签也是独立初始化。业务切页不改变地址，不形成可独立分享的会话路由。初始空会话是演示起点，不是在每次进入聊天时删除已产生的记录。

1.3 说明口径、提示与弹窗

  • “已实现”指可在本地执行；“演示”不等于消息已真实投递；“仅展示”指无业务点击处理；“待确认”指未定义或未接入，不擅自补成正式规则。
  • 字段逐项注明当前类型、来源、格式、空值与已有校验。代码未实现字数上限、权限或唯一性验证时，按未定义记录。
  • 同一时间只有一条notice。不同提示替换旧提示并重新计时，约2200ms消失；同句仍显示期间重复触发不重启计时。
  • 提示在手机上方覆盖显示，不可点击。聊天选择、图片和微信弹窗支持已提供的关闭/取消按钮、外侧和Escape；二维码小菜单优先关闭当前层。
  • 当前页面规则直接展示在原型右侧，随页面、视角和聊天弹窗切换，独立滚动；不发送消息、不清草稿、不取消当前选择。界面模拟身份切换不代表真实账号权限。

2. 起点：教师详情的聊天入口

2.1 入口与携带字段

元素/字段当前规范与来源点击及判断
底部顾问头像/气泡整按钮可访问名称“联系芦顾问”点整按钮进入用户侧顾问会话；不是打开老师本人会话
当前老师detailTeacherIndex对应detailRecord携带正在查看的老师；不固定王教员，不取上一张聊天卡片
教师卡片记录kind=teacher，record=当前老师名片名片字段按第8章；该入口不采集新的教师资料
接待顾问固定芦顾问当前没有真实客服分配
欢迎语您好，我是芦顾问，请问有什么可以帮您？固定原文，不带robot=true
两条消息时间浏览器当前本地24小时HH:mm同一次入口产生的两条时间一致；ID分别递增

2.2 执行顺序及重复进入

  1. 获取当前老师名片与当前HH:mm。
  2. 在共享会话末尾追加家长消息：sender=user，text=[老师] 姓名，attachment.kind=teacher，record为当前老师。
  3. 紧接追加顾问消息：sender=adviser，正文为固定欢迎语。
  4. 收键盘，关闭常用语/加号、记录选择、待发与查看图片、微信名片等临时工具，清提示。
  5. 强制chatRole=user，进入聊天并滚至最新。
条件结果
原会话为空新增两条开场消息
原会话非空保留原记录，在末尾再追加两条
再次主动点击入口每次都追加一组，无教师ID去重、时间去重或节流
仅重渲染、切视角、返回聊天不自动新增开场
老师卡片进入详情后直接返回不新增消息，原视角、草稿和记录保留
后续普通文本发送只增加发送者消息，不自动回复

例：从吴教员的聊天入口进入，家长右侧为吴教员名片，顾问左侧为固定欢迎语。切顾问视角只翻转这两条归属，不重发。教师详情其他按钮不在本次说明内。

4.4 滚动与布局规则

  • 当前身份消息在右侧，另一方在左侧；文字分别使用青绿和白色气泡；头像按sender决定。
  • 顾问信息条/用户偏好条固定在聊天区上方；测量实际高度后调整滚动区起点，长字段换行不遮挡消息。
  • 进入聊天、切视角、消息变化、键盘高度变化、面板变化、资料条高度变化时，下一帧滚到会话底部；图片加载完成也滚底。
  • 上述逻辑不会判断用户是否正在阅读旧消息，因此新消息或布局变化可能把正在阅读的位置带到最新。
  • 没有语音按钮；输入栏仅输入框、加号、有有效草稿时的发送按钮。

5.3 切换判断

  1. 选择已处于的视角：直接返回，不清面板、不改草稿、不新增消息。
  2. 选择另一视角：收键盘，关闭常用语/加号、记录选择、待发图片、查看图片、企业微信名片，清当前提示，再切chatRole。
  3. 用户草稿与顾问草稿分别保留；A侧输入未发送→切B→再切A，A草稿恢复。
  4. 历史消息id/sender/text/attachment不变，只重算左右位置、头像和对话对象。
  5. 常用语、加号权限和弹窗“发送给谁”文案跟随当前视角。
  6. 不自动新增欢迎语，也不是实际账号切换或客服授权。

15. 右侧规则面板、实现索引与维护

15.1 右侧规则面板

  • 原型与规则面板左右并排，直接显示当前场景规则正文，不再使用右下角“原型说明”悬浮入口，也不在聊天弹窗内重复放说明链接。
  • 教师详情只在未打开其操作弹窗时展示聊天入口规则；消息页只展示私信规则。首页、通知页、教师详情其他功能弹窗不展示规则面板。
  • 用户聊天显示通用聊天规则；顾问聊天先显示顾问资料、视角差异，再列通用聊天规则。
  • 常用语/加号展开时显示面板规则；待发图片/查看图片显示图片规则；微信名片/识别菜单显示二维码规则。
  • 老师选择显示老师筛选、共同选择规则与老师名片字段；需求单和订单选择分别显示共同选择规则及本类型字段，不混入其他卡片字段。
  • 定位优先级：微信名片/菜单→图片预览→老师选择→需求/订单选择→常用语或加号面板→当前聊天视角；只改变筛选值、不改变当前场景时，保留规则阅读位置。切场景后规则区回到顶部。
  • 规则正文独立滚动，不驱动手机滚动，不清草稿、所选卡片或消息；聊天弹窗打开时仍显示对应规则并可滚动。窄画布保留左右布局，通过画布横向滚动查看，避免面板压盖手机内容。
  • 页脚“完整说明”在新标签打开当前场景章节；“下载 MD”下载独立文件。右侧正文、网页版、MD均由同一原文生成，不依赖第三方服务。
  • 读取规则期间显示“正在加载当前页面规则…”；读取失败显示“规则暂时无法加载，可查看完整说明。”，不影响聊天操作。
